# Maps and geographic layers

This folder stores source-traceable geographic data for Ermita, Manila, with a detailed focus on Rizal Park. Status reflects repository files and import reports reviewed on 2026-10-18; counts are not claims of survey-grade completeness.

## Imported data currently present

- **Interactive real-geometry preview:** open [`preview.html`](preview.html) in a browser (or via GitHub Pages/raw hosting) to view the OSM road centerlines and OSM building polygons with layer toggles and source-tag popups. It fetches the two committed GeoJSON files directly; it is a lightweight preview, not a cadastral or survey-grade GIS.
- **Building height evidence audit:** `qa/building-height-evidence.csv` and `qa/building-height-evidence-report.json` are generated by `../scripts/audit_building_height_evidence.py`. A source-tagged `height` is kept distinct from `building:levels`; no floor-count-to-meter conversion or invented height is made. Run workflow `ermita-building-height-audit.yml` to refresh them.
- **OpenStreetMap:** `generated/import-report.json` reports 8,040 elements, 7,825 GeoJSON features, 1,533 building/building-part features, 5,661 POI/infrastructure rows, and 44 street-sign/signal features. OSM coverage depends on mapped features and query extent.
- **Microsoft/Bing building footprints:** `external/ermita-microsoft-building-footprints.geojsonl.gz`; import report records 12,132 footprints clipped to the project's rectangular AOI. Source imagery vintage is 2016–2020. This is supplemental, not official Philippine government data.
- **Real road/path geometry:** `generated/ermita-road-network.geojson` contains 1,445 mapped OSM way centerlines (motor roads, service roads, footways, pedestrian ways and steps); 366 ways have a name. `generated/road-network-export-report.json` records the extraction, and `../streets/street_segments.csv` indexes the same geometry. These are real OSM coordinates, not generated street lines, but the cache must still be checked for local omissions.
- **OSM–Microsoft geometry QA:** `qa/building-footprint-comparison.csv` and `qa/building-footprint-comparison-report.json` are the first metric-CRS screening comparison. It compared 1,528 OSM building/building-part polygons with 12,132 Microsoft polygons. Initial report classifications: 109 OSM polygons with IoU ≥ 0.50; 956 partial/conflicting overlaps; 419 nearby candidates with no material overlap; and 44 with no Microsoft candidate within 8 m. The Microsoft-side unmatched candidates are not proof that a building is missing from OSM. See `qa/README.md` for interpretation and limitations.
- **Official NPDC park references:** `../rizal-park/source-data/npdc-assets/` contains the technical park map, brochure, GIS distribution/thematic mapping report, and Western Section Development Project document, with source URLs and SHA-256 checksums in `import-report.json`. These are reference documents, not yet georeferenced GIS layers. Existing NPDC 2024 tree CSVs were not re-imported.
- **DPWH road and bridge layers:** four clipped GeoJSON layers are recorded in `external/dpwh-road-bridge-batch-import-report.json`: 286 national-road features, 990 road-surface features, 939 lane-count features, and 61 bridge-inventory features. Check per-layer source vintages before treating attributes as current.
- **Street signs and furniture:** see `generated/ermita-street-signs-and-signals.geojson` and `generated/ermita-street_furniture.csv`.
- **Street names and segments:** see `../streets/`.

## Asset retention rule

For every future import or generated asset, commit the reusable file to this repository whenever its license and size allow, alongside a source/import report and README/source-register entry. See the repository-wide [data asset policy](../../DATA_ASSET_POLICY.md) for the required metadata and validation checklist.

**Satellite imagery exception:** the preview currently streams Esri World Imagery tiles from the provider; those tiles are not in the repository. Esri's terms do not automatically grant redistribution rights, and its dedicated World Imagery export item requires an ArcGIS Online subscription or developer account. We must not bulk-copy ordinary display tiles into GitHub without explicit authorization. For a persistent local aerial image, the next step is to acquire a source whose terms explicitly allow download and redistribution, or use an authorized export and store its source/license evidence with the files.

## Important distinction: imported vs. reconciled

OSM and Microsoft have both been imported and now have a first-pass geometric comparison, but they have **not** been reconciled into one authoritative footprint layer. Do not concatenate them blindly: outlines may overlap, differ, reflect different dates, or include neighboring areas inside the rectangular crop. Preserve source IDs and provenance, then manually review matches and conflicts before creating a merged derivative.

The project AOI is a rectangular crop, not an administrative boundary or cadastral parcel boundary. OSM absence does not prove a feature is absent on the ground. IoU and boundary distances are screening metrics, not survey accuracy.

## Preferred formats

GeoJSON for interoperable vector exports; GeoPackage for larger GIS datasets; CSV for tabular indexes; retain raw source files separately when size and licence terms permit it.
