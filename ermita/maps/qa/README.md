# Building footprint comparison — first-pass QA

Generated by `ermita/scripts/compare_building_footprints.py`.

## Outputs

- `building-footprint-comparison.csv`: one row per OSM polygon plus Microsoft polygons not selected as an OSM polygon's best counterpart.
- `building-footprint-comparison-report.json`: source paths, CRS, counts, classification totals, and limitations.
- Workflow: https://github.com/saeedhub101/Adam-City/actions/workflows/ermita-footprint-comparison.yml

## Method

1. Read the existing OSM GeoJSON and clipped Microsoft GeoJSONL.gz; neither source is modified.
2. Keep OSM polygon/multipolygon features tagged `building` or `building:part`.
3. Transform both datasets to EPSG:32651 (UTM zone 51N) before area/distance calculations.
4. Query candidate polygons that intersect or lie within an 8 m buffer; compute intersection-over-union (IoU), intersection divided by smaller area, boundary distance, and area ratio.
5. Classify the best counterpart for each OSM polygon, and emit Microsoft polygons that were not selected as a best counterpart for further review.

## First-pass result

The initial run compared 1,528 OSM polygons with 12,132 Microsoft polygons and produced 13,151 CSV rows. OSM-side best-counterpart categories were:

- 109 strong overlap candidates (IoU ≥ 0.50)
- 956 partial or conflicting overlaps (IoU ≥ 0.10, or at least 50% of the smaller polygon covered)
- 419 nearby candidates with no material overlap
- 44 with no Microsoft polygon within 8 m

Microsoft-side categories in the report are 11,496 Microsoft-only candidates, 40 unselected overlap candidates, and 87 nearby candidates. “Microsoft-only” means no OSM polygon was found within the screening threshold; it does **not** establish that the feature is a valid building or that OSM is wrong.

## Limitations and review rules

- The AOI is a rectangle, not a legal park or cadastral boundary.
- Microsoft source imagery vintage is 2016–2020; OSM edit dates vary.
- Best-counterpart selection is not a one-to-one conflation algorithm; adjacent buildings, building parts, and duplicate outlines need human review.
- Small IoU can reflect different segmentation or roof/ground outline conventions, not necessarily a bad feature.
- Do not automatically import Microsoft-only candidates into OSM or promote this table to a canonical merged layer.
- Verify a representative sample against permitted current aerial imagery, official survey data, or field observations.


## Building-height evidence audit

- `building-height-evidence.csv` inventories OSM polygon building/building-part features and preserves source-tagged `height`, `building:levels`, `min_height`, and `roof:shape` separately.
- `height_tagged` means the source has a `height` tag; it is not a guarantee of a field-verified measurement.
- `levels_only_no_height_inferred` deliberately does not convert storeys to meters.
- `height_unknown` means the source provides no explicit height tag. Do not replace unknown values with visually plausible guesses.
- Refresh using `python ermita/scripts/audit_building_height_evidence.py` or the `ermita-building-height-audit.yml` GitHub Actions workflow.
